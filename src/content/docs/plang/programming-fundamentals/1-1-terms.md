## 개요
프로그래밍을 배울 때 자주 접하게 될 핵심 용어를 정리한다.

## 본문
### 1) 빌드 파이프라인
텍스트 파일이 CPU가 이해하는 명령어로 변환되는 단방향 파이프라인.

* **소스코드 (Source Code)**: 소프트웨어를 제작하기 위해 사람이 작성하는 원본 텍스트.
* **컴파일 (Compile)**: 고수준 언어로 작성된 소스코드를 컴퓨터가 이해할 수 있는 저수준 언어로 번역하는 과정.
* **컴파일러 (Compiler)**: 소스코드를 기계어나 어셈블리어로 번역하는 프로그램.
* **어셈블리어 (Assembly Language)**: 0과 1로만 이루어진 기계어를 사람이 읽을 수 있는 기호로 1:1 대응시킨 저수준 언어.
* **어셈블러 (Assembler)**: 어셈블리어를 기계어로 번역하는 프로그램.
* **목적 코드 (Object Code)**: 컴파일러와 어셈블러에 의해 번역되었지만, 외부 연결이 완료되지 않아 단독 실행은 불가능한 기계어 파일.
* **링커 (Linker)**: 여러 목적 코드 파일과 외부 라이브러리를 결합해 최종 실행 파일을 생성하는 프로그램.
* **기계어 (Machine Language)**: CPU가 별도의 번역 과정 없이 해독하고 실행할 수 있는 바이너리 명령어 집합.

> **흐름 요약**: 소스코드 $\rightarrow$ 컴파일러/어셈블러 $\rightarrow$ 목적 코드 $\rightarrow$ 링커 $\rightarrow$ 최종 실행 파일(기계어)

#### 1-1) 컴파일러와 어셈블러 차이
컴파일러와 어셈블러는 소스코드를 기계가 이해할 수 있는 형태로 변환한다는 점에서 유사하다. 하지만 **어디서 시작해서 어떻게 번역하는지**에 차이가 있다.

| 구분 | 컴파일러 | 어셈블러 |
| :--- | :--- | :--- |
| 입력 코드 | 고수준 언어 | 어셈블리어 |
| 출력 결과 | 어셈블리어 또는 목적 코드 | 기계어 |
| 변환 방식 | 복잡한 문법 분석 및 코드 최적화 | 명령어 기호와 기계어의 1:1 단순 치환 |

### 2) 시간의 분기선
프로그램의 생애주기를 나누는 두 가지 절대적인 시점. 오류가 발견되는 타이밍과 원인을 구분하는 기준이 된다.

#### 2-1) 컴파일 타임 (Compile-time)
작성한 소스코드를 기계어로 번역하여 실행 파일로 만드는 시점.

* **컴파일 타임에 수행되는 작업**
  * 구문 분석: 코드의 문법적 오류 검사. (괄호 누락, 세미콜론 누락 등)
  * 의미 분석: 변수와 함수의 타입의 일관성 등 검사. (숫자 변수에 문자 대입 등)
  * 코드 최적화: 프로그램의 성능 향상을 위한 소스코드 최적화.
* **컴파일 타임 에러**
  * 프로그램이 실행조차 되지 않고 번역 단계에서 발생하는 오류.
  * 예) 철자 오타, 정의되지 않은 변수 사용, 문법 오류 등

#### 2-2) 런타임 (Runtime)
번역이 완료된 실행 파일이 메모리에 적재되어 CPU에서 실제로 동작하는 시점.

* **런타임에 수행되는 작업**
  * 메모리 할당 및 해제
  * 사용자의 입력 처리
  * 외부 데이터(파일, 네트워크 등) 접근
  * 실제 연산 수행
* **런타임 에러**
  * 컴파일은 완료했으나 프로그램이 실행되던 도중 강제 종료되는 오류.
  * 예) 0으로 나누기, 존재하지 않는 파일 열기, 메모리 부족 등

#### 2-3) 컴파일 타임 VS 런타임
| 구분 | 컴파일 타임 | 런타임 |
| :--- | :--- | :--- |
| 의미 | 번역하는 시점 | 작동하는 시점 |
| 검사 주체 | 컴파일러 | 컴퓨터 하드웨어 및 운영체제 |
| 오류 발견 | 실행 전 (빌드 실패) | 실행 중 (프로그램 강제 종료) |

### 3) 개발 환경
코드를 작성하기 위해 사용하는 작업 도구.

#### 3-1) 텍스트 에디터
텍스트를 편집하고 저장하는 데 집중된 가벼운 소프트웨어.
* 코드를 작성할 수 있지만, 자체적으로 컴파일하는 기능은 없다.
* 컴파일 및 실행을 위해 별도의 컴파일러 설치나 터미널 명령어 입력이 필요하다.
* 예) VS Code 등

#### 3-2) IDE (통합 개발 환경, Integrated Development Environment)
코드 작성부터 컴파일, 실행, 디버깅까지 모든 기능을 포함한 소프트웨어.
* 하나의 소프트웨어로 컴파일부터 실행까지 모두 처리할 수 있다.
* 예) Visual Studio 등

### 4) 코드의 재사용
미리 작성된 코드를 조립하여 프로그래밍하는 방식.

#### 4-1) 라이브러리 (Library)
자주 사용되는 기능(수학 연산, 그래픽 출력 등)을 미리 구현해 모아둔 코드들의 묶음.
* 필요할 때마다 호출하여 사용한다.
* 프로그램의 전체 실행 흐름과 제어권은 내가 작성한 코드에 있다.

#### 4-2) API (Application Programming Interface)
프로그램이나 시스템이 다른 프로그램에서 사용되기 위해 규정해 놓은 인터페이스.
* 내부 구현 코드를 몰라도, API 명세서에 적힌 함수 이름과 입력값만 사용해 원하는 결과를 얻을 수 있다.

---

### 5) 결함과 정상화
의도와 다르게 작동하는 문제를 추적하고 바로잡는 과정.

#### 5-1) 버그 (Bug)
프로그램이 작성자의 의도와 다르게 오작동하거나 멈추는 결함.
* 프로그램 실행을 멈추는 치명적인 오류부터 계산 결과가 잘못 나오는 논리적 결함까지 모두 포함한 개념이다.

#### 5-2) 디버깅 (Debugging)
코드에 존재하는 버그의 발생 위치와 원인을 찾아내고 수정하는 작업.

#### 5-3) 디버거 (Debugger)
디버깅을 효율적으로 수행할 수 있도록 돕는 소프트웨어.

* **주요 기능**
  * **중단점 (Breakpoint)**: 코드 실행을 특정 지점에서 강제로 멈추는 기능.
  * **단계별 실행**: 코드를 한 줄씩 실행하며 동작 흐름을 추적하는 기능.
  * **변수 감시**: 멈춘 시점에서 메모리와 변수에 저장된 실제 값을 실시간으로 확인하는 기능.
