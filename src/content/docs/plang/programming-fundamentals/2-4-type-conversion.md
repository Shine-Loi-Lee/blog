## 개요
메모리에 저장된 데이터의 자료형을 다른 자료형으로 바꾸는 타입 변환에 대해 설명한다.

---

## 타입 변환의 필요성
CPU는 기본적으로 동일한 자료형의 데이터끼리만 직접 연산할 수 있도록 설계되어 있다.

* **연산 규격 일치**: 서로 다른 크기와 해석 방식을 가진 데이터는 직접 연산할 수 없다.
  * 예) `int`(4바이트 정수)와 `double`(8바이트 실수)는 비트 저장 구조가 완전히 다르기에, 두 데이터 사이의 연산은 내부적으로 정수를 실수로 변환한 뒤에야 이루어진다.
* **함수 호출 규격 충족**: 특정 라이브러리 함수가 요구하는 정확한 매개변수 타입에 데이터를 맞추어야 할 때 사용된다.
* **데이터 손실 방지 및 정확한 연산 결과 도출**: 표현 범위가 좁은 타입끼리의 계산 도중 오버플로우가 나거나 소수점 정보가 버려지는 것을 막기 위해 더 넓은 타입으로 변환하여 연산의 정밀도를 보호한다.

---

## 암시적 변환 (Implicit Conversion)
개발자가 별도의 변환 코드를 작성하지 않아도, 컴파일러나 인터프리터가 프로그램의 문맥을 분석하여 자동으로 자료형을 바꾸는 방식.

### 수치 승격 및 확장 (Numeric Promotion & Widening)
표현 범위가 다른 수치 데이터끼리 연산할 때, 데이터 손실을 막거나 하드웨어 연산 효율을 높이기 위해 더 넓은 타입으로 자동 확장하는 변환.

* **하드웨어 기본 단위로 확장**: 레지스터 크기보다 작은 단위(`byte`, `char`, `short`)의 연산 시 기본 정수 규격(`int`)으로 자동 승격되어 계산된다.
* **표현 범위 확장**: 정수와 실수가 연산될 때 정수가 실수로 변환되거나, 작은 실수(`float`)가 큰 실수(`double`)로 변환되어 연산 정밀도를 유지한다.

```cpp
char a, b;
printf("a, b의 크기: %d, %d\n", sizeof(a), sizeof(b));
printf("a + b의 크기: %d\n", sizeof(a+b));

// 실행결과
// a, b의 크기: 1, 1 -> char의 크기
// a + b의 크기: 4 -> int의 크기
// char 연산 시 하드웨어 기본 정수 규격인 int로 자동 승격되어 계산된다.
```

### 불리언 변환 (Boolean Coercion)
조건문 등에서 참/거짓 판단이 필요한 위치에 수치, 문자열, 객체, 포인터 등이 입력되었을 때 불리언(`true`/`false`)으로 자동 해석되는 변환.

* **숫자 및 주소**: `0`이나 `null`(널 포인터/빈 참조)는 `false`로, 그 외의 값이나 유효한 메모리 주소는 `true`로 간주된다.
* **문자열/배열**: 동적 언어 등에서는 빈 문자열(`""`)이나 빈 배열이 `false`로 평가되기도 한다.

### 암시적 변환의 위험성
* 컴파일 에러나 경고 없이 타입이 바뀌므로, 개발자가 실수로 다른 타입을 섞어 썼을 때 의도치 않은 연산 결과나 논리적 오류를 유발하기 쉽다.
  * 예) 문자열과 숫자의 모호한 결합, 부호 있는 정수와 부호 없는 정수의 비교 왜곡 등

## 명시적 변환 (Explicit Conversion)
개발자가 직접 타입을 명시하여 강제하는 방식.

* **C 스타일 캐스팅**: 변환할 대상 앞에 괄호로 타입을 붙이는 방식.
  * 직관적이지만 위험한 메모리 변환까지 강행한다는 단점이 있다.
  * 예) `(int)3.14` $\rightarrow$ `3`
* **함수 스타일 캐스팅**: 타입을 함수나 클래스 생성자처럼 호출하는 방식.
  * 현대 고수준 언어에서 널리 쓰인다.
  * 예) `int(value)`
* **키워드 명시 캐스팅**: 변환의 의도나 안전 수준을 명확히 구분하는 방식.
  * 예) C++의 `static_cast<int>(x)`, Rust의 `x as u32`

---

## 형변환 시 주의점
* **데이터 절단 (Data Truncation)**
  * 표현 범위가 큰 정수형을 작은 정수형으로 강제 변환할 때, 작은 크기의 메모리에 맞추기 위해 비트열이 버려지며 왜곡되는 현상.
  * 4바이트 정수 `300`(이진수: `... 0001 0010 1100`)을 1바이트 정수로 변환하면 하위 8비트(`0010 1100`)만 남아 `44`가 된다.
* **정밀도 손실 (Precision Loss)**
  * 표현 정밀도가 더 낮은 자료형으로 변환될 때 미세한 정보가 손실되는 현상.
  * 실수를 정수로 변환: 반올림이 아닌 소수점 이하 자리가 완전히 버려진다. (`3.99` $\rightarrow$ `3`)
  * `double`(64비트)을 `float`(32비트)로 변환: 소수점 끝자리가 잘려 나가 오차가 발생한다.
* **부호 변환 버그 (Signed/Unsigned Misinterpretation)**
  * `signed`와 `unsigned`의 최상위 비트 해석 방식 차이에 따라 값이 극단적으로 변하는 현상.
  * `-1`을 `unsigned`로 변환하면 부호를 의미하는 최상위 비트가 수의 크기로 해석되어 `unsigned`의 최댓값(약 42억)으로 바뀐다.
* **정수 나눗셈 (Integer Division)**
  * 나눗셈에 참여하는 피연산자가 모두 정수인 경우, 결과를 실수가 아닌 소수점을 버린 정수로 계산된 뒤 목적지 변수에 대입되는 현상.
  * `1 / 2`의 결과는 `0`이 먼저 계산된 후 실수 변수에 대입되어 `0.0`이 저장된다.
  * 최소 한쪽을 실수형으로 명시적 변환해야 정확한 값을 얻을 수 있다. (`1.0 / 2` 또는 `(double)1 / 2`)
